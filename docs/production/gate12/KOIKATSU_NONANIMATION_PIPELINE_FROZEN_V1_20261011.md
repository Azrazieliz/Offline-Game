## Frozen process invariants

1. **Source fidelity and provenance.** SHA-256 every original GLB and preserve all used source-resolution image payloads, skinned geometry, materials/texture assignments, vertices/UVs, skin weights, reference matrices, bone hierarchy, morph/accessor payloads and accessories. Never remove/resize source geometry or textures to accommodate development-host RAM. Configurable runtime presentation and compression may be reversible derivatives, never replacements for originals.
2. **Strict interchange.** The verified source sharder accepts actual glTF 2.0 binary .glb using exactly one source skin, and checks referenced mesh, morph, texture and material invariants. Any second export that does not conform needs an explicit supported adapter and independent test. No silent rig invention or use of a different character's rest pose.
3. **Stable identity and guarded import.** Require character_id matching [A-Za-z][A-Za-z0-9_-]{2,63}, preserve original source SHA-256, per-shard SHA-256 and content provenance. The byte-preserving source conversion is build_kk_export_generic.py; use stage_new_koikatsu_character.ps1 to stage privately. Use import_kk_character_guarded.ps1 without -Execute first for an evidence-only import plan. Every new actual native UE import must produce real .uasset results and validation receipts; plan-only PASS is NOT native import PASS. No overwrites.
4. **Exact native visual parts.** Separate future characters under /Game/Experimental/KoikatsuConverted/<character_id>/...; accept variable valid mesh/primitive counts, not a fictional universal requirement of 19 parts or 25 primitives. Verify every native mesh, per-component original skeleton, reference pose, orientation/scale, blend shapes, textures, material parameters and equipment attachment points in an independent fresh Unreal editor run.
5. **Persistent mobile face/material ownership.** Imported morph-driven face/body/eye instances must resolve to project-owned persistent parent shaders with MATUSAGE_MORPH_TARGETS saved; confirm via cold editor reload and actual Android shader cook. Never replace the source materials or bake away morphology. Individual skin/toon/eye/hair shader presentation improvements remain modifiable and separately must be checked on S26.
6. **Existing game integration.** The real character Blueprint must inherit the existing Offline-Game movement/gameplay input, retain touchscreen, gamepad, persistence, equipment and interactions, replace only its experiment-specific avatar geometry, and preserve world and camera semantics. Keep Unreal gameplay native mesh identities intact; forbid one character's skeleton/animation from being assigned to another unless compatibility is genuinely proven.
7. **Reproducible Android path.** UE5.8.3 Windows-native engine compile, exact native Android arm64 link, Android_ASTC playable-map cook using proven serial/per-package GC settings, isolated APK packaging/signature/native build-ID checks, and installation under a dedicated experimental package rather than modifying or clearing com.azrazieliz.OfflineGame. Require on-device screenshot/video and runtime traces before claiming physical validation.
8. **Gate 11 provenance.** Supply stable IDs, hashes, editable source and interchange, dependency inventory, native .uassets, validation/QA status and physical receipts. The fixture remains an unapproved engineering experiment; do not claim ARTIFACT_READY without Gate 11's explicit validation and approval.

## Not frozen / open engineering gates

- **All animation content and runtime motion design:** The 171 native procedural exact-skeleton clips are engineering placeholders, not approved natural walk/run/swim/jump/dodge quality. Gate 12 remains free to replace/retarget animations, build coherent cross-part body state, add proper blending, ground-contact and air/swim transitions, repair facial-expression motion coexistence and improve camera occlusion. This must not destructively change immutable source geometry or Koikatsu cards.
- **Universal integration for future exports:** Generic source sharding and import *planning* were tested; the generic full native -Execute import, actual generic author_kk_playable_from_descriptor.py for a second character and second-character S26 result have NOT been demonstrated. Therefore the non-animation reference workflow is frozen, but a one-click fully automatic conversion guarantee is NOT certified. The first new Gate 01 character is the next generalized-pipeline test.
- **Visual overlays/scalability:** Surface toon aesthetics, eyes/highlights, alpha sorting, clothing/physics/collision, optional non-destructive mobile quality profiles, camera view and quantified renderer FPS/thermal validation may improve without reopening this source-handling contract.
- **Authority:** Gate 00 controls creative direction and production-start policy, Gate 01 source character creation, Gate 12 engineering/device acceptance, Gate 11 registry/production intake. No Gate 11 ARTIFACT_READY is implied.
